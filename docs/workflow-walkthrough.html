bayescycle — complete workflow walkthrough

Non-linear loop: reject → respecify → simulation gate → real fit → ArviZ → provenance

prior gate rejects & respecifies single backend · Bayesite simulate · recover · sbc n = 200 NUTS run.json → SQLite

Overview

This page runs a complete, non-linear bayescycle workflow end-to-end on a single backend (Bayesite) for a Bayesian linear regression (n = 200). The loop is deliberately not a straight line: a first model with wide priors is rejected at the prior-predictive gate, the model is respecified, and only then does the simulation gate (prior predictive, simulate, recover, single-scenario recover, SBC) and the real fit (sample, diagnose, posterior predictive, posterior check) proceed, finishing with ArviZ visualization.

The architectural invariant: every command is a typed state transition that writes the same bayescycle run-directory v0 contract, plus an append-only run.json (bayescycle.run.v1) provenance record. The model is authored in bayeswire; bayescycle owns run-directory paths, artifact serialization, and backend dispatch through narrow per-operation integration modes; Bayesite and bayesite-viz consume the artifacts.

Iteration 1 — rejected at the gate

1A wide-prior model fails prior predictive

Before touching the data, check what the model believes a priori. This one believes nonsense.

INPUTmodel_v1.py deliberately wide priors
"""Iteration 1: priors are far too wide; the prior-predictive gate rejects it."""

from bayeswire import Data, Observed, Param, model
from bayeswire.constraints import Positive
from bayeswire.distributions import HalfNormal, Normal


@model
class LinRegWide:
    x = Data.vector()
    alpha = Param(Normal(0.0, 100.0))
    beta = Param(Normal(0.0, 100.0))
    sigma = Param(HalfNormal(50.0), constraint=Positive())
    mu = alpha + beta * x
    y = Observed(Normal(mu, sigma))

bayescycle prior-predictive model_v1.py --data inputs.json \
  -o run-prior-rejected/ --backend bayesite --engine $BAYESITE --seed 123 --draws 400
WRITErun-prior-rejected/prior_predictive.ndjson header + 400 draws + trailer

A flat linear regression with scalar intercept, slope, and a positive scale — now with priors on a credible scale.

"""Iteration 2: priors tightened to a plausible scale after the gate failed."""

from bayeswire import Data, Observed, Param, model

Because these records are flat and self-describing, the filesystem workflow serializes directly into a relational index (docs/run-provenance-db.py → docs/walkthrough-runs.sqlite). The cross-run artifact lineage — e.g. run-sim's simulated_data feeding run-recover-fit — is recovered as rows in workflow_edges:

SELECT r.workflow, r.run_dir, r.kind, r.backend FROM runs r ORDER BY r.id;

SELECT p.run_dir AS produces, e.producer_role, c.run_dir AS consumes
FROM workflow_edges e
JOIN runs p ON p.id = e.producer_run_id
JOIN runs c ON c.id = e.consumer_run_id;
