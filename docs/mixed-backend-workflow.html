Mixed-backend workflows are explicit — and non-linear

Bayescycle separates backend intent from backend-native data files. A workflow plan is resolved before any run directory is created, and stages exchange canonical bayescycle.data.json.v1 artifacts. This page is generated from a real executed run: a wide-prior model is rejected at the prior-predictive gate, the model is respecified, then a Bayesite simulation hands off to an in-process jaxstanv5 recovery fit.

model v1
wide priors→ prior predictive
jaxstanv5✗ respecify
back to square one→ simulate
bayesite→ recover fit
jaxstanv5→ recover-check
bayesite

Plan the backends before any run directory exists

The mixed plan is mixed only because every stage backend is assigned explicitly:

[workflow]
mode = "mixed"

[stages.simulate]
backend = "bayesite"

[stages.recover]
backend = "jaxstanv5"

uv run bayescycle workflow-plan --config workflow.toml
{
  "backends": {},
  "mode": "mixed",
  "stages": {
    "recover": "jaxstanv5",
    "simulate": "bayesite"
  }
}

Partial assignments (--simulate-backend alone) and backend-specific options that select no stage (--engine with --backend jaxstanv5) still fail before any writes — see the run-directory contract docs.

Iteration 1 — rejected at the gate

A wide-prior model fails prior predictive

"""Iteration 1: priors are far too wide; the prior-predictive gate rejects it."""

from bayeswire import Data, Observed, Param, model
from bayeswire.constraints import Positive
from bayeswire.distributions import HalfNormal, Normal


@model
class LinRegWide:
    x = Data.vector()
    alpha = Param(Normal(0.0, 100.0))
    beta = Param(Normal(0.0, 100.0))
    sigma = Param(HalfNormal(50.0), constraint=Positive())
    mu = alpha + beta * x
    y = Observed(Normal(mu, sigma))

bayescycle prior-predictive model_v1.py --data inputs.json -o run-prior-rejected/ --backend jaxstanv5 --seed 123 --draws 400

The prior predictive distribution of y is wildly implausible: prior-implied y ∈ [-765, 677] while the observed data sits in [-5.0, 6.5].

Decision: reject and respecify. The priors carry far more mass than the measurement scale can justify. The workflow loops back to model declaration rather than proceeding to simulation — a prior-predictive check is a gate, not a formality.

Iteration 2 — respecified

Tightened priors pass the gate

"""Iteration 2: priors tightened to a plausible scale after the gate failed."""

from bayeswire import Data, Observed, Param, model
from bayeswire.constraints import Positive
from bayeswire.distributions import HalfNormal, Normal


@model
class LinReg:
    x = Data.vector()
    alpha = Param(Normal(0.0, 2.5))
    beta = Param(Normal(0.0, 2.5))
    sigma = Param(HalfNormal(1.0), constraint=Positive())
    mu = alpha + beta * x
    y = Observed(Normal(mu, sigma))

bayescycle prior-predictive model.py --data inputs.json -o run-prior/ --backend jaxstanv5 --seed 123 --draws 400

Prior-implied y ∈ [-19, 17] now brackets the observed range without dwarfing it.

Canonical artifact handoff: Bayesite simulate → jaxstanv5 fit

Bayesite simulates fake data from a known truth and writes a canonical data document:

bayescycle simulate model.py --data inputs.json --truth truth.json -o run-sim/ --backend bayesite --engine $BAYESITE

run-sim/simulated_data.json is bayescycle.data.json.v1; its declared inputs (data, truth) and generated observed y are backend-neutral.

The recovery fit then runs in-process on jaxstanv5, consuming the canonical artifact through the adapter without ever reading Bayesite-native JSON:

bayescycle sample model.py --data run-sim/simulated_data.json -o run-recover-fit/ --backend jaxstanv5 --seed 2 --chains 4 --warmup 400 --draws 500

The append-only provenance makes the cross-backend edge explicit. The fit's data input is exactly the simulator's output:

{
  "simulate (bayesite) output": "run-sim/simulated_data.json",
  "fit (jaxstanv5) input.source_path": "run-sim/simulated_data.json",
  "input.format": "bayescycle.data.json.v1",
  "input.sha256": "sha256:fcb3b5b1777b3e09..."
}

Recover-check: jaxstanv5 fit vs Bayesite-supplied truth

Bayesite recover-check reads the jaxstanv5 posterior stream (4 chains × 500 draws) and compares it back to truth — no fingerprint barrier because the check consumes only the fit and the truth:

bayescycle recover-check run-recover-fit/ --truth truth.json --targets targets.json --interval 0.8 --engine $BAYESITE

Provenance is serializable

Every run directory carries an append-only run.json (bayescycle.run.v1). Across this mixed workflow:

run dirkindbackendinputsoutputs
run-prior/prior-predictivejaxstanv5dataprior_predictive
run-prior-rejected/prior-predictivejaxstanv5dataprior_predictive
run-recover-fit/samplejaxstanv5dataposterior
run-sim/simulatebayesitedata, truthsimulated_data

These flat records serialize directly into docs/walkthrough-runs.sqlite (see docs/run-provenance-db.py), where the cross-backend handoff above appears as a row in workflow_edges:

SELECT p.run_dir, e.producer_role, c.run_dir, e.consumer_role,
       p.backend || ' -> ' || c.backend AS handoff
FROM workflow_edges e
JOIN runs p ON p.id = e.producer_run_id
JOIN runs c ON c.id = e.consumer_run_id;
-- mixed/run-sim  simulated_data  mixed/run-recover-fit  data  bayesite -> jaxstanv5
